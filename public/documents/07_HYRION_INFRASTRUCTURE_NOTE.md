## 5. HYRION Core Functions

## 5.1 Evidence Registry

Purpose:

To register every mining-related evidence item.

Evidence types:

- licenses,
- permits,
- maps,
- GIS files,
- technical reports,
- lab assays,
- field samples,
- photos,
- GPS points,
- agreements,
- capital documents,
- governance decisions,
- meeting notes.

Each item should have:

- ID,
- title,
- type,
- owner,
- source,
- date,
- status,
- access level,
- related product,
- review state,
- version.

---

## 5.2 Data Permissions

Purpose:

To control who sees what.

Access levels:

| Level | Use |
|---|---|
| Level 0 | Public-lite overview |
| Level 1 | Controlled institutional access |
| Level 2 | NDA access |
| Level 3 | CDG review |
| Level 4 | Legal / IP review |

HYRION prevents uncontrolled circulation of sensitive mining data.

---

## 5.3 Field Chain of Custody

Purpose:

To connect field evidence to verifiable records.

Each field item should link:

- sample ID,
- location,
- GPS,
- image,
- collector,
- date,
- description,
- laboratory,
- assay result,
- related map,
- related decision.

This is critical for PR3538746 and future smart exploration products.

---

## 10. Technical Implementation v0.1

For the first digital window:

- HYRION can be represented as structured data files.
- Document metadata can be stored in local JSON/TS files.
- Access can be simulated by labels.
- Sensitive files can remain manually controlled.
- Product rooms can show locked cards.
- CDG review access can be prepared as a future gated area.

Recommended data fields:

```ts
type EvidenceItem = {
  id: string;
  title: string;
  product: "isseksi" | "pr3538746" | "corporate" | "technology";
  type: "license" | "map" | "report" | "sample" | "assay" | "agreement" | "memo";
  status: "draft" | "ready" | "under-review" | "locked";
  accessLevel: "public-lite" | "controlled" | "nda" | "cdg-review" | "legal";
  version: string;
  owner: string;
  lastUpdated: string;
};
```
